# 004 - What the demo shows

Status: in progress

## Contract
Objective and motive: rethink what the demo shows a visitor, not what it does inside.
The user, after testing change 003, still "does not understand half the process": the 7-step menu does not lead to Explore, step 07 is unreachable (clicking returns to 3 or 4), the path is not linear, there is too much hard text and unexplained elements such as traces, and claims like "no data" or "the value is X" mean nothing to a visitor who does not know the study.
The user suggests showing where each value comes from in the study to fill the sentences, instead of asking the visitor to believe or check.
Out of scope: agent, tools and data internals beyond what the new screens need.
Restrictions / decisions that need the user: none open; D1-D6 answered (option A, proposal in `.lavish/004/propuesta.html`).
Current authorization and limits: on 2026-11-03 the user approved the change and the recommended decisions; implement on branch `claude/ui-redesign-b81e12`, update PR 15 with green CI, never merge; no new dependencies.

## Decisions
- Approach (D1-D5, option A): a landing that shows a real draft sentence first, then 4 screens in one line (study, ask, decide, draft) with one numbering and a "Next" on each; every placed number, quotation and decision opens its source from data the code already holds; screen 3 keeps one key finding and the per-sex decisions with nothing preset; UI in ES/EN with plain finding names and the draft in English, labelled; technical detail in a folded "Inside" panel per screen.
- Change 003 criteria are superseded where they conflict: C1 (reading path per page), C4 (four-stage journey on the landing), C12 (format line), C13 (93-word cap, now 60) and C15 (three numbered Explore stages); the REAL/RECORDED/SIMULATED badges of C5 give way to three provenance colours, while its contrast and focus guarantees stay.
- Screen 3 keeps the existing rule that people decide adversity and code computes the NOAEL (`noael_rule` in `src/cairn/decisions.py`); "decide the NOAEL" means the visitor makes the per-sex decisions that set it and confirms it.

Supervisor, 2026-11-03: the 60-word cap of C14 is applied screen by screen inside I3, I4, I6, I7 and I8 (each redesign removes the text that the cap would otherwise force out twice); the global cap at 60 is asserted at I8 close. I2 is done with C13 (E13, E14).
Supervisor, 2026-11-03, on the Jefe's question about the answer unit: C14 as frozen in commit 477f3a1 states "with the draft body and each recorded answer counted as one unit", so counting `answer-unit` as one word applies the criterion, it does not loosen it. The answer is not collapsed: it appears only after the visitor clicks a question (state `ask_before` has no answer, 58 ES / 57 EN words); after a click the answer is visible in full. Evidence: `tests/test_word_cap.py::test_rendered_counter_counts_an_answer_unit_as_one_word` and the `ask_*` states under `ASK_WORD_CAP = 60`. Counting the answer's real words would need either collapsing every answer behind a second click or a stricter criterion; that is the user's call (D8).
