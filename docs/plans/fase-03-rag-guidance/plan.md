Layout proposed by the planner (names may be adjusted by the implementer, the split may not):
- Inputs, versioned by hand: `data/guidelines/manifest.json` and the 4 PDFs (decision O2), `data/guidance/weights.json` (repo ID, pinned revision and SHA-256 per weights file), `data/guidance/fixed_queries.json`, `data/guidance/calibration.json` (decision O4), `tests/evals/e4_questions.json`.
- Generated by `cairn guidance build` (Makefile target `guidance`) and committed: `data/guidance/passages.json`, `data/guidance/retrieval_cache.json`, `data/guidance/highlights/` (PNG per quoted page plus `highlights.json` with the boxes); tests rebuild and compare, nobody edits them by hand.

- Weights live outside the repo in a cache folder read from `CAIRN_MODELS` (default under the user cache); `make weights` downloads them once with the pinned revision and SHA-256; tests that need them fail with "weights missing: run make weights", never skip.
- Replay paths (loop replay, tests over recordings, the app) read `retrieval_cache.json` and never import the reranker or the embedder.

Fixture recordings before the real ones (as in 02b):
- Until increment 14 lands, tests that need G1-G3 or the new prompt replay hand-written fixtures under `tests/fixtures/recordings/` with `"source": "fixture"`, never under `recordings/`.
- `test_recordings_metadata_*` keeps rejecting any file under `recordings/` whose source is not Bedrock in an EU region.
